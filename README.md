# Protocol Signature Finder

CLI-утилита для автоматического поиска пользователя, подписавшего финальный протокол процедуры, и формирования прямой ссылки на его лог-запись.


## Проблема

При разборе инцидентов нужно было понять, кто именно подписал финальный протокол процедуры.
Раньше это делалось вручную: открывался веб-интерфейс, по номеру процедуры искался протокол,
затем через отдельную БД определялся пользователь, и вручную собиралась ссылка на лог с нужным
временным интервалом (±2 минуты от публикации). На одну процедуру уходило 5–10 минут.

## Решение

Скрипт делает всё за один проход:
1. Ищет процедуру по регистрационному номеру сразу в нескольких БД.
2. Находит финальный протокол (`discriminator LIKE '%final%'`).
3. Через `organization` БД определяет `externalId` подписавшего пользователя.
4. Формирует готовую ссылку на лог с интервалом ±2 минуты от времени публикации протокола.

Поддерживает пакетную обработку — можно ввести сразу несколько номеров процедур через запятую.

## Результат

- Время поиска: **5–10 минут → несколько секунд**
- Убрана ручная работа по сборке ссылки и сопоставлению пользователей
- Можно обрабатывать список процедур за один запуск

## Стек

- Python 3
- SQLAlchemy (через внутренний `ConnectionFactory`)
- Работа с несколькими БД одновременно: `procedures`, `lot`, `protocol`, `signature`, `organization`

## Запуск

```bash
git clone git@github.com:username/protocol-signature-finder.git
cd protocol-signature-finder
pip install -r requirements.txt
python main.py
# Введи номер процедуры через запятую: 12345678, 87654321
```

Пример вывода:

```
================================================================================
https://example.com/httpAction/user/12345/?uri=67890&dateTime-from=01.01.2025%2012%3A00&dateTime-to=01.01.2025%2012%3A04&
================================================================================
Обработка всех процедур завершена!
```

## Примечания

- Использует внутреннюю библиотеку подключения к БД `supp_adel` — в репозитории
  заменена заглушкой, реальные названия БД и хосты вынесены в конфиг.
- Скрипт рассчитан на ручной запуск инженером техподдержки при разборе инцидента.
